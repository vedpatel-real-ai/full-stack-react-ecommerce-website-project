# Operations

Inspect the staff Exceptions view and event history for unresolved online orders. Match the internal order UUID and merchant reference against the independent provider record. Do not collect card details, full payloads, keys or shipping addresses in support logs. The HTTP adapter emits a correlation ID on errors and limits customer-facing details.

A missing callback leaves the payable pending. The worker interface returns an explicit unconfigured state until an approved inquiry adapter exists. Once authorized, schedule reconcile(store, inquiry) on a private server every 15 minutes. Each run claims at most 25 due rows with row locks, retries at increasing intervals and stops after five claims per order. A claim does not certify payment. Once retries are exhausted, staff must resolve the discrepancy with the merchant. Expired time alone never declares a captured or failed charge.

Alert the responsible operator on exhausted retries, conflicting capture references, unexplained delays, rejected evidence or a provider timeout surge. There is no live pager configured. Track age from creation and next inquiry time. Keep reconciliation records until the owner approves retention and archival. Obtain authoritative records and independent sign-off before any financial correction.

A refund request creates an audit event only. Record the merchant's actual settlement separately through a controlled evidence workflow. Staff archive records and record return or cancellation separately from payment. Cancelled fulfilment still needs review if a late capture arrives. Delete consented inbox data according to the approved retention schedule; financial statements follow a separate policy.
